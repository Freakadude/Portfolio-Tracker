- Backups and restore in the app: System has a Backups and restore section. It lists the backups on the server (the nightly ones and the copies Folio takes before an update and before a restore), makes one now, downloads one (without your saved API keys unless you ask for them, so a copy that leaves the server does not carry them), brings in a backup file made elsewhere (it is checked before it is kept), and deletes one. To restore, pick a backup, read what will happen and type RESTORE: Folio checks the file, sets it aside, and restarts; on start, before anything opens the database, it swaps the backup in and brings it up to the current version, and the worker restarts to follow. What was there before is kept as a "before a restore" backup, so a restore can be undone by restoring that one. A file that has gone bad changes nothing and the System page says so. You are signed out afterwards (the sessions come from the backup). It relies on the stack restarting its containers, which it does [FR-SY-07]. See ADR 0044.
- Sign-in through Tailscale (optional, off by default): if you reach Folio through Tailscale Serve and set `FOLIO_TAILSCALE_USER` (your tailnet login) and `FOLIO_TRUSTED_PROXIES` (the address Tailscale Serve connects from), the login page offers "Sign in through Tailscale" when a request really comes through Tailscale Serve as that user. The identity header is trusted only from that address and only for that user, because anyone who can reach Folio directly can write the same header; with either setting missing nothing changes. A tailnet sign-in does not ask for the two-factor code; the password and the code still work. A typo in the address list stops the web container from starting, with a message [FR-SY-04]. See ADR 0043 and docs/deployment.md.
- Two-factor sign-in: Settings, Security can turn on an authenticator-app code at sign-in (Aegis, 2FAS, Google Authenticator, 1Password and the like). You scan a QR code (or type the key), confirm with a code the app shows, and are given ten one-time recovery codes, shown once and kept only as hashes, for a lost phone. From then on signing in asks for the password and then a code, and a code or recovery code works once; five wrong codes lock the sign-in for a while like five wrong passwords do. A set-up you do not finish changes nothing, so you cannot lock yourself out half way. Turning it off, or making new recovery codes, needs your password and a current code, so a stolen session alone cannot remove the second factor; each change is in the audit log, without any secret [FR-SY-03]. See ADR 0042. New dependency: segno (QR codes, no dependencies of its own).
- Projection: Reports has a Projection tab (and there is a Projection dashboard widget) showing what your portfolio could be worth over the next 1 to 40 years if returns were random with an expected return and volatility you choose and you add a monthly amount you choose (none by default, as you have no contribution plan). It draws the median with a band from the 10th to the 90th percentile of 2,000 simulated paths, against what you would simply have paid in; the assumptions are written under the chart and in its table view, and last year's measured return and volatility are shown to help you choose. The same assumptions and seed always give the same chart. It is an illustration of your assumptions, not a forecast [FR-PF-12]. See ADR 0041.
- Rule backtest: Strategies has a Backtest tab. Choose one rule or all of them and a range of dates (up to three years) and Folio checks the rules against the portfolio as it was on each past trading day, then lists when they would have fired with the value that made them fire (for a drift rule, how far from its target in percentage points), after the same repeat filter that live signals go through, so the list is what your inbox would have shown. The rules are the ones in the version you are looking at, with that version's sleeve members and targets. Rules that depend on something that was not kept for past days (price freshness, the contribution plan's dates, thesis review dates, the ETF holdings of each day) are named as not backtestable, with the reason, instead of being guessed. Nothing is saved or sent [FR-ST-06]. See ADR 0040.
- Tax-support report and export: Reports now has three tabs. "Tax support" gives, for any calendar year (and any account), what a tax return asks: the value and the holdings on 1 January and 31 December, the money put in and taken out (purchases and deposits in, sales and withdrawals out, as the returns count external flows), income before and after what was withheld, the costs of buying and selling and other fees and taxes, the proceeds, cost and result of what was sold, and the change in the unrealized result. It downloads as CSV, and "Print or save as PDF" prints just the report. The current year runs to today and says so, and holdings without a price are called out. "Export" downloads every posted transaction and the open positions as CSV or JSON; the transactions file has the columns the import wizard recognises as Folio's own, so importing it again (into a new account, for example) needs no choices and gives the same quantities, cost basis, realized results and income, including dollar trades at your broker's rate and the taxes you paid or had withheld. The CSV import also learned a "taxes" column [FR-PF-11, FR-TX-13]. See ADR 0039.
- Ask the portfolio: Insights has a question box (and a dashboard widget of the same name) where you ask the agent about your portfolio in your own words, and a position's page has "Analyse this position" with an optional question of your own. The agent only reads: it looks at your data with the same read-only tools as its reviews and answers, and the answer lists the data it used, tool by tool, with the rows each returned. An answer is shown only if every amount, quantity, weight or percentage in it is a number one of those tools returned (so in privacy mode no euro amount can appear) and it cites only tools the agent really used; otherwise you are told it was not shown and why. It never makes a recommendation or a draft transaction, it is labelled as AI-generated, it counts against the AI budget and the daily run cap, and it needs the agent switched on with a key [FR-AG-08, FR-DB-09]. See ADR 0038.
- Event calendar: News has a Calendar tab listing what is coming up: the ECB's and the Federal Reserve's rate decisions for 2026 (shipped with Folio from their published schedules, which you should check against ecb.europa.eu and federalreserve.gov), the earnings dates of the equities you hold when you switch on EODHD's earnings calendar under Settings (it needs a plan that includes it, uses one call of the daily budget a week, and a refusal is shown on the System page without stopping anything), and events you add yourself. Every row can be changed or deleted, and a date you delete is not brought back. The evening before an event (from 18:00) the agent writes a short brief that appears in Insights; when the agent is off, has no key, has used its budget or fails, a plain reminder is sent instead, so the day-before notice never depends on the model. The agent's `get_upcoming_events` tool now returns this list [FR-NW-09]. See ADR 0037.
- Weekly deep review and quarterly review: on Sunday evening (from 18:00, a time you can change under Settings, Agent) the agent runs its weekly deep review of the whole portfolio with the stronger model and leaves a digest in the inbox, once a week. After each quarter ends, Folio writes a review of your active strategy without any model: for each sleeve its drift from the target at the month ends, on its worst day and how many days it spent outside its bands, the signals that fired by rule, and what became of the agent's advice (your decisions and, where measured, the outcomes). It puts one item in the inbox per quarter, never two, and the same summary is on Strategies, Quarterly review, where you can look at any of the last eight quarters and put a finished one in the inbox yourself [FR-AG-07, FR-ST-08]. See ADR 0036.
- Track record of the agent's advice: every day after the closes Folio compares each recommendation with the price of its subject 7, 30 and 90 days after it was made (the price it stored at the time) and Insights shows, by action type, how many were measured, the hit rate and the average price change, and the same by what you decided (accepted, rejected, no decision). Only two kinds of advice have a direction to judge: direct new money counts as a hit when the price is not lower, a trim when it is not higher; hold, watch, review, rebalance and information are measured but never counted. The comparison is price only, in the instrument's own currency, and with so few recommendations the numbers are small samples, which the page says. A horizon with no price yet waits, and after two weeks without one is closed as "no price" [FR-AG-06]. See ADR 0035.

- Fixed: a news feed on a non-standard port (a local feed, for example) had its robots.txt looked up on the standard port and could not be fetched; the robots.txt is now read from the same address and port as the feed [FR-NW-02].
- News sources and fetching: a list of sources under Settings (the ECB's and the Federal Reserve's press-release feeds and EODHD's news for your tickers come ready; you add issuer feeds), each with a language, a trust weight, how often to check and the macro series it speaks to. A feed can be previewed (its last ten items) before it is saved. Fetching is polite: conditional requests (a "not modified" answer costs no parsing), robots.txt obeyed, ten seconds between requests to one site, and a failing source waits longer each time (up to a day) and shows its error in Settings and on the System page. Only the headline, a summary of at most 500 characters, the link and the time are stored; article pages are never fetched. EODHD news costs five calls of the daily budget per ticker and only runs while the closes' share is safe [FR-NW-01, FR-NW-02, FR-NW-03]. See ADR 0026.
- News stories and links: items about the same story from different sources (within 48 hours, similar headlines) are grouped into one cluster, and each cluster is linked to what you hold: directly (an ISIN, a ticker or a name in the text, or a ticker EODHD tagged it with), through an ETF that holds the company (the link shows the company's weight in the ETF, for example 5.2 %), and, for a central bank's rate and currency news, to the sleeves whose rules watch those series, so a Fed rate decision links to a gold sleeve that watches real yields. Each link gets a relevance from how it was found, how much of your portfolio it touches, how much the source is trusted and how fresh it is [FR-NW-04, FR-NW-05, FR-NW-10]. See ADR 0027.
- AI agent foundations (nothing runs yet): the Anthropic connection is in place with prompt caching, optional web search limited to trusted domains and structured output. Every call is recorded with its tokens and its cost in euro (from a price table under Settings, Agent, which you should check against Anthropic's pricing page), and a call that could take the month past your budget (default 5 EUR; news may use at most 1.50 of it) is refused before it is made, with one inbox notice per month, critical if a critical signal is open. A daily cap on runs and a per-run token cap stop loops. Prompts are versioned text files and each run records which wording it used. Settings, Agent can switch the agent off, and "Test the key" makes a tiny call to prove the key and show what it costs. The System page shows the month's runs and cost against the budget and says why the agent is idle (no key, off, or paused) [FR-AG-04, FR-AG-09, FR-AG-10]. See ADR 0028.
- News triage: stories linked to what you hold (and a few unlinked ones from sources you trust, at most ten a day) are read by the cheap model in batches, which scores each from 0 to 100 for your portfolio, says whether it is positive, negative, mixed or unclear and over what horizon, names the holdings it touches and may add thematic and macro links the text matching missed. A story scoring 60 or more, or touching a position above 10 % of your portfolio, is read again by the stronger model. An impact of 80 or more on a holding is one high notification (the lock-screen text names nothing). News copy only ever reaches the model inside a block marked as untrusted, with angle brackets removed, and the model can only pick holdings and sleeves from the lists it is given. "Useful" and "not relevant" on a story adjust the source's trust (0.1 for every five net "not relevant" marks) and the alias that matched. The News list can be filtered by holding (directly or through an ETF), impact, direction, source and date. All of it stays inside the news share of the AI budget and stops, with a notice, when that is used up [FR-NW-05, FR-NW-06, FR-NW-07, FR-NW-08]. See ADR 0029.
- The gate for the AI agent's advice (no agent run yet): every recommendation the model proposes must cite evidence the run really saw, trades must come from one of Folio's own calculators for the same holdings, every amount, quantity or percentage in the text must match a number a tool returned (so a changed amount, or any euro figure in privacy mode, is refused), a buy right after a sell on the same holding (or the reverse) within 14 days is refused unless it is critical and rests on newer evidence, and the answer must follow the agreed structure. A refused item is kept with its reason and never shown as advice. Ten fixed evaluation scenarios, written before the prompts are tuned, check all of this, including a model that was fooled by an instruction hidden in a news story [FR-AG-03]. See ADR 0030.
- The AI agent runs: every weekday from 19:30 (a time you can change) it reads your strategy, the open signals, the linked news and its own recent advice, investigates with thirteen read-only tools (positions, allocation including look-through, signals, news, macro series, the calculators, a what-if simulator, its recommendation history; web search only on the trusted sites you list), and in a second step writes its recommendations in a fixed structure. The code gate then decides what you see: advice with no real evidence, a trade without a calculation, an amount that was not in a tool result (in privacy mode, any euro figure) or a quick reversal of recent advice is refused, kept with its reason and never shown as advice. What passes reaches the inbox with your routing, labelled as AI-generated and not financial advice, with its calculation, evidence, confidence, expiry and a badge when it departs from your principles; a quiet day reads "nothing needs attention". It also runs for a high or critical signal (once per subject per day), for a news story scoring 70 or more, and when a contribution is due. The whole run, from the context it was given to each tool call, its answer and what it cost, can be read afterwards [FR-AG-01, FR-AG-02, FR-AG-03]. See ADR 0031.
- Deciding on the agent's advice: each recommendation can be marked seen, accepted, rejected (with an optional one-line reason that later reviews can read) or snoozed for 1 to 30 days. Accepting can turn the calculation behind the advice into draft transactions, which you confirm one by one on Insights, but only while that calculation still holds today (if the portfolio or the prices changed so that it would give different orders, you are told and nothing is made; you can still accept and record the trades yourself). Items past their expiry leave the open list at once, and the worker marks them expired and wakes snoozed ones. Every decision is in the audit log [FR-AG-05]. See ADR 0032.
- Look-through and news in the web app: on an ETF's page you can upload the issuer's holdings file (it is previewed first, the column match can be corrected, cash and derivatives are listed as left out), see the saved snapshots (an old one is marked) and its largest holdings, and set the issuer's download address or EODHD so Folio refreshes it monthly. The Look-through widget lists your largest underlying companies, sectors, countries or currencies with where each sits (held directly, or inside which ETF at what weight), and the Allocation widget can look through ETFs. The News page lists stories with their impact, direction and horizon, what each is linked to (including through an ETF, with the weight), who reported it and a link to the original, filtered by holding, impact, direction, source and date, with "useful", "not relevant" and "wrong link" buttons that say what they changed. Settings, News lists the sources with their fetch status and errors, previews a feed before it is saved, and sets how stories are triaged; the System page names failing sources [FR-MD-09, FR-PF-05, FR-NW-01, FR-NW-07, FR-NW-08].
- The agent in the web app: Insights lists the agent's recommendations waiting for you, each labelled AI-generated and not financial advice, with its summary and reasoning, the orders from Folio's calculator, its evidence (signals, stories, data, web pages with links), when it expires and a separate badge with the reason when it departs from your principles. You can accept it, accept it and make draft transactions (blocked, with the reason, when the portfolio has changed since), open it in the What-if page, reject it with an optional one-line reason, snooze it for 1 to 30 days or mark it seen, and look back at what you accepted, rejected, snoozed or let expire. "Run a review now" asks the worker for one. Settings, Agent shows the month's cost against the budget and what news triage used, tests the saved key, and holds every agent setting. The System page lists the agent's runs with their cost and opens the whole trace of one: what it was told, each tool call, what it found, its answer and the verdict on each recommendation with the reasons for any it refused. The News and Signals dashboard widgets now show stories linked to your holdings, and the recommendations and signals waiting for you; Insights and the widgets update by themselves when a recommendation is made or decided [FR-AG-01, FR-AG-04, FR-AG-05, FR-AG-09, FR-NW-07].
- Look-through: open an ETF up into what it holds and add everything up by company, sector, country or currency, so a company you hold directly and inside two ETFs shows as one exposure with where it comes from (held directly, or inside which ETF and at what weight). What a holdings file does not name stays visible as "Other holdings of the ETF", and a fund without holdings is shown as itself, marked as a fund. Available as `look_through=true` on the allocation, as `/portfolio/look-through` (the top companies, with the share below them), in the allocation and look-through widget data, and in the What-if simulator, which now shows how the largest companies change. ## Editing transactions (between Phases 4 and 5)

- Any stored transaction, imported or typed, can now be edited from the position page: every row of a position's history has Edit and Delete, opening the same form as the Transactions page. The date, type, account, instrument, units, price, currency, rate, fees, taxes and note can all be changed (the type and the account were locked before). For a buy or a sell the form now shows the euro amount while you type, worked out by the server with the same arithmetic as saving (units times price at the rate, plus or minus fees and taxes), so it matches what is stored. Saving rebuilds the lots, the positions and the history from the earlier of the old and new dates; a change that would sell units you never held, or leave another trade without its lots, is refused in words and nothing changes. An imported row keeps its broker reference, so importing the same file again still recognises it.

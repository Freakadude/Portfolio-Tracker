# ADR 0059: The chat helper reads what the app shows, and each answer shows its cost

Status: accepted (2026-10-09). Extends FR-AG-08 and FR-DB-09; supersedes the part of ADR 0049 that said the helper could not see what is on screen.

## Context
Asked what the drawdown chart does, the helper answered that it "could not read the chart's own data", although a dashboard with that chart was open. Two causes. It had thirteen tools, none of which returned drawdown, volatility, returns by period, monthly returns, correlations, attribution, income, transactions, the watchlist or the inbox, so anything outside the thirteen was honestly unreadable. And the page hint told it only "a dashboard" and to use that "only to understand the question".

## Decision
- **The widgets are the source.** Every number on a dashboard already comes from one tested place, `dashboards/data.py` `compute`. The helper gets two tools on top of it: `get_widget` (any widget type, with a period and the widget's own options as JSON; a bad option comes back as the message the owner would see) and `get_view` (the page the owner has open: a dashboard with its saved filters and its widgets, the first ten with their data and a plain sentence on what each is for; a position page with the position; any other page with what it shows and which tools read it). So the helper quotes exactly what the screen shows, and a new widget type is readable without new code. One generic tool instead of one per widget keeps the tool list short, which the model handles better and costs fewer tokens on every call.
- **Three more tools for data that is not a widget:** `get_transactions`, `get_watchlist`, `get_inbox`. The tool list is now eighteen.
- **Privacy mode is unchanged and applies to the new tools.** Widget data passes through a projection that removes every euro amount of the owner's money (`view.private`): fields ending in `_eur` anywhere, and per widget type the ones that are only amounts (value history, return bridge, income, the projection's euro points, the holdings table's value, result, day change and income columns); the ratio next to an amount is kept. A test runs every widget type against the test book in privacy mode and fails if any of its euro sums reaches the model. Switching privacy mode off (Settings, Agent) is how the owner gets euro answers.
- **Results are small and clean.** A long dated series is cut to 24 points (12 in the view of a whole dashboard) with its low and high and the count; decimal noise such as `-4E-40` becomes `0`. Notes the owner wrote and news headlines are wrapped as untrusted data like all outside text.
- **The code gate compares magnitudes.** A drawdown is a negative ratio (-0.0523); the answer says "5.23%" or "-5.23%". The percentage check now matches the written figure against the absolute value of a tool result, so negative results (drawdowns, negative drift, losses) can be quoted; before, only the positive ones could. A figure still has to be a tool result to the digits shown.
- **The model is told where the owner is.** The page sentence names the dashboard and its id and says that a question about "this", "here" or a chart is about it and starts with `get_view`. `ask_investigate` is version 2 and `ask_answer` version 3: a chart or figure is explained from the "about" sentence the tool returns, followed by the owner's current figures, and "could not read" is allowed only after a tool error. There is no JSON scenario for this under `tests/agent_eval` because that harness covers the recommendation gate; the scripted-model test `tests/integration/test_agent_chat.py::test_a_question_on_a_dashboard_is_answered_from_the_data_on_it` plays the same part.
- **Each finished answer ends with its cost** ("This answer cost €0.02."), from the run's `cost_eur` that the answer already carried, in the small-amount form of ADR 0052 (below one cent it reads "< €0.01", not "free"). It is shown in the chat panel and in the Ask box, and not while the answer is being written or when the run cost nothing.

## Consequences
An answer about a dashboard may call `get_view` and then `get_widget` for a widget, so a question costs a little more than before (a longer tool result is read once or twice); the monthly budget guard still stops it. The helper reads the dashboard's saved filters, which the page saves about a second after a change, so a filter changed a moment ago may not be seen yet; what is typed into a form and not saved is not visible to it.

# ADR 0014: Return, risk, attribution and drift conventions

Status: accepted (2026-10-05)

## Decisions
- **Time-weighted return (TWR).** One point per calendar day with end value, external flow and income. The day's return is `(V_t + income_t) / (V_{t-1} + flow_t) - 1`: the flow is treated as made at the start of the day (spec FR-PF-03). Daily returns are chained. Income counts as return because, with cash tracking off, it leaves the portfolio. A day whose starting capital is not positive has no return and is skipped, and so is the day on which everything was sold, because there is no end value to measure.
  - *Known limit:* flows are in euro at the trade price while the previous value is at the previous close, so a trade day with a large price move is slightly off. This is the convention the spec asks for and the one a spreadsheet reference uses; it is documented rather than corrected.
- **XIRR.** ACT/365, annualised. The start value is an outflow on the baseline day, contributions are outflows, withdrawals and income inflows, and the end value an inflow on the last day. Solved in `x = ln(1 + r)` by Newton's method kept inside a bisection bracket, in Decimal at 40 digits. `None` when the flows do not change sign or the rate lies outside -99.9999% to +100,000%.
- **Risk.** Volatility is the sample standard deviation of daily TWR returns times the square root of 252. Weekends and holidays carry a zero return, so only trading days (days on which some held listing has a close) are used; dropping a zero-return day leaves the compounded index unchanged. Drawdown runs on the TWR index, not on value, so a deposit cannot fake a recovery. Sharpe is the annualised return less the risk-free rate over the annualised volatility. Beta is covariance over the benchmark's variance. Correlation is Pearson on the common days and needs at least five of them; a constant series has none.
- **Attribution.** A position's contribution is `V_end - V_start - flows + income`. All positions plus an "other" line (costs and income that belong to no position) add up exactly to the portfolio's period P&L. Percentage points use one common denominator, the Modified Dietz capital (start value plus flows weighted by the share of the period they were invested, a first-day flow counting in full). The points therefore sum to the portfolio's Modified Dietz return, which is shown as the return used for attribution; it differs a little from TWR, as the two always do.
- **Drift.** `analytics.allocation.drift(actual, target, band)` is the only definition. Weights, targets and drifts are fractions of the portfolio. The API calls it, and so will the Phase 3 rules engine, so a rule can never act on a different number from the one on a chart.
- **Per-position net invested.** The ledger keeps `PositionState.net_invested_eur` (buys and transfers in add cost, sales subtract net proceeds, transfers out subtract the cost moved) so position and sleeve returns and attribution have a flow per position. Deposits and withdrawals belong to the account.

## Consequences
Position and sleeve figures are computed from the same daily series as the portfolio, so they agree with it by construction. Because the conventions are in one module each, a change (for example end-of-day flows) is a local edit with golden tests that say exactly what moved.

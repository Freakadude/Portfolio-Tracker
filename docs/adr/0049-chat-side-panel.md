# ADR 0049: A chat side panel that fronts "Ask the portfolio"

Status: accepted (2026-10-09). Extends FR-AG-08 (see ADR 0038). It is new scope, beyond the original specification, asked for by the owner.

## Context
The owner wants a collapsible panel on the right of every page where they can talk to the app's AI helper about their portfolio, holdings, news and strategies. "Ask the portfolio" already answers such questions, but only one at a time, on two pages, with no memory of the question before.

## Decision
- **The panel is a front for the existing Ask engine, not a second chat engine.** A reply is still made in two steps by the worker (investigate with the read-only tools, then write the answer in a fixed structure) and is shown only if the code gate passes it: every figure must be a number a tool returned in that turn and every citation a tool the run called. The privacy mode, the budget and the daily cap apply as they do for Ask, and the helper still cannot change anything or recommend a trade.
- **A chat is a chain of `ask` runs that share a `thread` id.** The browser makes the id (a uuid, kept in its local storage; "New chat" makes another) and sends it with each question, with the route the owner is on. Both are stored in the run's `context`, so there is no new table and no migration, and every turn already has its full trace, cost and data list on the System page. `GET /agent/chat/{thread}` returns the turns oldest first (it looks through the 300 most recent ask runs, which is ample for one user). The id must match `[A-Za-z0-9_-]{8,40}`; the route must be a plain app path and is dropped otherwise.
- **A follow-up is shown the earlier turns as context, not as data.** The last six exchanges (the owner's question and the accepted answer, each cut to 600 characters, wrapped as untrusted text) are added to the question, with the page the owner has open ("the page of the position X") to resolve "this one". The message says the figures in it must not be reused: the gate looks only at what the tools return in the current turn, so a follow-up that wants an earlier number has to have the tools fetch it again, and an answer that repeats one from memory is refused. This costs a little speed and keeps the property that every number on screen is a tool result. The existing ask prompts are unchanged (versions stay at 1); the conversation text is built in `folio/agent/ask.py`.
- **No streaming, and the wait is said plainly.** The two steps and the worker queue mean a reply takes up to a minute and arrives whole. The panel shows "Looking at your data" and polls every two seconds while a turn is pending, and not at all while it is closed or idle. A synchronous in-process chat would be quicker but would drop the gate or duplicate the tool loop; the strategy interview, which needs no tools, stays on its own page and is linked from the panel.
- **Layout.** A round "Ask Folio" button sits at the bottom right of every page; `Ctrl+/` (or `Cmd+/`) toggles the panel and Escape inside it closes it. The panel is 24 rem wide. From the `lg` breakpoint it is part of the page row, so the page narrows beside it instead of being covered; below that it is a full-height overlay with a backdrop. Its open state is kept in the browser, the unsent text survives closing, and nothing is polled or fetched while it is closed. It is hidden when printing.

## Consequences
No schema change; one request field pair (`thread`, `page`), one response field (`thread`) and one endpoint. The cost of a message is that of an Ask (a few cents), the history in the message adds a little input. Old runs without a thread are untouched. The panel and the Insights "Ask" box share the answer rendering (`web/src/agent/AnswerBody.tsx`).

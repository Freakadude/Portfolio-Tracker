# ADR 0024: ETF holdings for look-through

Status: accepted (2026-10-05)

## Decisions
- **Two tables instead of one.** The spec lists a single `etf_holding_snapshot` table. Folio stores `etf_snapshot` (one ETF on one date, with its source and the share of the fund the file covers) and `etf_constituent` (one row per holding). A snapshot is replaced as a whole and deleted as a whole, and the analytics read "the newest snapshot of each ETF", which is one lookup instead of a `max(as_of)` subquery per ETF. Older snapshots are kept, so a later phase can show how an ETF changed.
- **A file is the main source (Q2).** The owner stays on free data tiers, and EODHD's ETF fundamentals need a paid plan, so an uploaded CSV is the normal path. Issuers publish holdings as CSV but not alike: iShares puts about nine lines of fund details above the table and a legal footer below it, others start at the header, and column names differ ("Weight (%)", "% of net assets", "Weighting"). The parser finds the header row by its column names, matches columns by name, and the owner can correct the match on a preview before anything is stored. The file's own "as of" date is used when it states one. Cash and derivative lines are left out, so their weight shows up as "other holdings of the ETF". A weight column that adds up to more than 105 % is refused with a hint (percent or fraction?); one that adds up to about 1 is read as fractions.
- **Two optional automatic sources, monthly.** A download address per ETF (the issuer's direct CSV link), and EODHD fundamentals (`ETF_Data.Holdings`). A `lookthrough` job refreshes both on the first of each month and on demand. The address is fetched through the shared HTTP client (retries, circuit breaker, call counting) under the provider name `issuer`, which has no daily limit; a page that returns HTML instead of a CSV (a download button that needs a click) is reported rather than parsed. EODHD counts one fundamentals request as ten calls, so the budget charge takes a `weight` and the request is refused when fewer than ten calls remain. Which ETF uses which source is kept in the settings section `lookthrough`, keyed by instrument id, so the instrument table did not change.
- **Stale snapshots are called out, not hidden.** When the newest snapshot is older than 45 days (a setting), a low-severity item reaches the inbox, at most once a month per ETF. An ETF that never had a snapshot is not nagged about: look-through is optional, and an ETF without one is simply shown as itself in the analytics.
- **The EODHD fixture is derived from the documentation**, like the other EODHD fixtures (tests/fixtures/providers/README.md); it must be checked against a real response once a Fundamentals plan exists. The iShares-style CSV fixture is invented (fictional companies and weights) but follows the layout of the real files.

## Consequences
Look-through is only as fresh as the last file. The app never guesses holdings: an ETF without a snapshot is treated as one holding. Companies are matched across ETFs by ISIN where a file has one and by a normalised name otherwise (ADR 0025 describes the aggregation).

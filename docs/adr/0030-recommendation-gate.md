# ADR 0030: The code gate between the model and the owner

Status: accepted (2026-10-05)

## Decisions
- **The model proposes, code decides what is shown (FR-AG-03).** `folio/agent/validate.py` is pure code (mypy strict, in the coverage gate) that takes the composed answer, parsed from JSON, and what the run actually saw, and returns for each recommendation either the cleaned recommendation or the reasons it was refused. A refused item is kept in the run's trace with its reasons and never shown as advice.
- **Evidence has to be real.** Every recommendation cites evidence of one of five kinds, and each reference must resolve to something this run saw: a signal id from its context or from `get_signals`, a news cluster id it read, a tool it called (`metric`, optionally with a detail after a colon), a macro series it fetched, or a web page its search returned. References that do not resolve are dropped, with a note, and a recommendation with none left is refused. This is what stops a made-up citation, and a recommendation that rests on an injected web page that the search never returned.
- **Trade actions need a calculation.** `direct_contribution`, `trim` and `rebalance` must cite a `calculation_id` produced by `run_calculator` in this run and about the same subjects; other actions may cite one only if it exists. Folio's calculators decide every amount; the model only chooses which result to point at.
- **Figures in the text are checked against the tools.** Amounts, quantities and percentages the model writes (a number with a currency sign, a percent sign, "pp" or "units") must equal a number in a tool result or in the cited calculation, to the digits shown and written in any common format ("1.234,56", "1,234.56", "1 234"); a weight the tools gave as a fraction may be written as a percentage. Bare numbers (dates, "14 days") are not checked. In privacy mode (the default) the tools return weights and quantities but never euro amounts, so any euro figure in the text is refused: Folio fills in amounts itself from the calculation when it shows the item. This is the FR-AG-03 acceptance: a recommendation whose amount was altered is refused.
- **Anti-churn.** A buy-side action (a contribution) after a sell-side one (a trim) on the same subject, or the reverse, within 14 days of a live recommendation (new, seen, accepted or snoozed; not rejected or expired) is refused unless it is critical and rests on evidence newer than the earlier one. Rebalance and the non-directional actions (hold, watch, review a thesis, hedge check, info) are not opposites of anything.
- **Schema, strictly, in any case.** The reader accepts exactly the fields of appendix C (an extra or missing field refuses that item), compares enum values without regard to case, treats a blank `departs_from_principles` as none, clamps the expiry to 1 to 90 days, drops sources that are not https addresses, and refuses a second recommendation with the same action and subjects in one run. An item that departs from the principles keeps its reason and gets the departs badge.
- **Evaluation scenarios first.** `tests/agent_eval/scenarios/*.json` are fixed scenarios (a state, a recorded model output, what the gate must do): a recommendation that passes, nothing to report, an altered amount, churn with and without the critical exception, a principle departure, evidence that was never seen, a model that followed an injected instruction, euro amounts in privacy mode, schema and case, duplicates and sources. They were written before the prompts were tuned and before the run loop, and the next step replays the same files end to end with recorded model responses. A test checks that each scenario accounts for every recommendation it contains.

## Consequences
The gate is deliberately strict and can refuse a good recommendation because of how it phrased a number; the refusal and its reason are visible on the System page, which is how the prompts get tuned. It does not judge whether advice is wise, only whether it is grounded, calculated, consistent and in the agreed form.

# ADR 0019: The dashboard UI: react-grid-layout, hand-drawn charts, and chart colours

Status: accepted (2026-10-05)

## Decisions
- **react-grid-layout 2 for the grid** (MIT, TypeScript, React 18). It gives drag, resize, responsive breakpoints and per-breakpoint layouts, which is what FR-DB-02 asks for, without writing a drag engine. The breakpoints are widths of the dashboard area, not of the window: 900 px and up is the 12-column desktop layout, 560 px and up the 8-column tablet, below that one column (a phone at 390 px). Dragging is by a handle only, so a click on a chart or a button never starts a drag; a drag or resize that ends is saved, and the settings dialog also takes a typed column, row, width and height, which is the keyboard way to arrange widgets.
- **Lightweight Charts for series over time, hand-written SVG and HTML for the rest.** Value history, drawdown, comparison and price charts reuse the library the position page already loads, with a crosshair that reads every series at the pointer, a legend for two or more series, and a separate pane (never a second axis on the same plot) for volume. Donut, treemap, drift bars, the waterfall, income columns and the heatmaps are small components of our own, which avoids a second chart dependency. The dashboard code is a lazily loaded chunk, so the chart libraries are fetched only when a dashboard is opened.
- **Colours come from the data-visualisation palette method.** Identity colours are six fixed hues in a fixed order (validated for colour-blind separation in light and dark with the palette checker; light mode has three hues below 3:1 contrast, so every chart has a legend, labels where they fit and a table view). A named thing keeps its colour when values change; past six things the rest fold into "Other" in the muted tone. Gains and losses, over- and underweight, and correlation use the blue-red diverging pair with a neutral grey midpoint, always together with a sign, an arrow or a number, never colour alone. Totals in a waterfall are neutral grey so they are not mistaken for gains. Large figures use proportional digits; columns of numbers use tabular digits.
- **Every chart has a table view and a drill-down.** The table view is a toggle on the widget (NFR-11). Clicking a slice, bar, cell or point opens the list it stands for: holdings filtered to a group, a position, or transactions for a date or month (FR-DB-06). A registry test fails when a chart widget has no drill-down target.
- **Live updates** invalidate the widget data when the stream reports a new close or quote; the previous picture stays on screen at reduced opacity until the new data arrives, so nothing flashes.

## Consequences
The widget registry on the web side and the library on the server must list the same widget types; a test checks the count, and the server refuses unknown types, so a mismatch is caught in CI rather than by the owner.
